# 録画試験のCI失敗と改善案（2026-10-02）

## 原因

[Static release checks #29](https://github.com/kajirudo/dopa-fit/actions/runs/36942580674)では、単体・配布ハッシュ・通常運動・PWA・音声・準備・成果カードの試験は通過し、最後の録画試験で失敗した。

Linux runnerではMediaRecorderが作ったMP4の映像をWebCodecsでデコードできず、Canvas再生＋MediaRecorderへの切り替えが発生した。動画は約15秒のMP4として生成されたが、試験が編集方式を無条件で`webcodecs`と決め打ちし、正常な`canvas`出力を不合格にした。録画対応と編集用デコード対応は同じ条件ではない。

## 修正

- 素材の収録前に動画・音声のデコード対応も確認する。H.264／AACを編集できず、VP8／Opusに対応する端末ではWebM素材を収録する。完成動画のMP4優先は維持する。
- 収録と書き出しのCanvasは不透明にする。VP8素材に不要な透明情報が付くと、編集ライブラリがBlob Workerで色・透明度を合成しようとして既存CSPに遮断される問題も再現した。完成画面に透明度は不要なので、素材の側で余分な処理をなくす。
- WebCodecsがない端末や対応確認に失敗する端末では、再生可能なMediaRecorder形式とCanvas書き出しを維持する。
- 編集時にも実際の各トラックのデコード可否を確認し、未対応ならCanvas方式へ移る。
- 試験は素材の実際のデコード可否と出力エンコード可否から期待方式を判定する。高速方式が使える環境では高速方式での成功を要求する。未対応を模擬した試験では、切り替え後の動画の再生を必須にする。
- 完成動画の音声検証にも、WebCodecsとAudioContextの対応差を反映する。実際の音声サンプル数とRMSを検証し、無音や音声欠落を通さない。
- 再試行・次の運動で古い書き出しエラーを消し、診断には収録形式・編集方式・切り替え理由を残す。
- CIはUbuntu 24.04へ固定し、Node 24対応の公式Actionsへ更新する。成功・失敗を問わず、JSONレポートと画面画像を7日間保存する。合成試験の動画や利用者の写真はアップロード対象にしない。

ローカルでVP8素材の経路を再現する場合は、`DOPA_RECORD_CODEC_PROFILE=vp8`を設定して`npm run test:record-browser`を実行する。

## 次の改善案

1. **実機の優先検証**：iPhone Safari／ホーム画面PWAで3・10・20分の運動から、顔被覆・メモリ・音声付き保存／共有まで確認する。顔追跡方式やBudgetの昇格は結果が揃ってから決定する。
2. **生成待ちの案内**：運動終了後だけ、編集方式と実測進捗から待ち時間の目安を示す。運動中の動画完成カウントや終了の誘導は追加しない。
3. **共有する尺の選択**：将来、終了後に15／30／45／60秒を選べるようにする。最初の版の45秒と、時間制限のない運動は維持する。

デスクトップ試験やCIの成功を、実機の顔被覆・長時間メモリ安全性の合格とは扱わない。
